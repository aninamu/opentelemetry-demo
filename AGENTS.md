# AGENTS.md

## Purpose and scope

This file is an operator playbook for autonomous coding agents
working in this repository.

Repository context:

- Project: OpenTelemetry Astronomy Shop Demo
- Type: Polyglot microservice e-commerce system
- Runtime: Docker Compose (default local/dev path)

Use this file for repo-specific execution guidance. For product
context and contribution policy, also see `README.md` and
`CONTRIBUTING.md`.

## 60-second quick start (cloud agent path)

Run from repository root:

```bash
docker version
docker compose version
make start-minimal
curl -fsS http://localhost:8080/ > /dev/null && echo "UI reachable"
```

Expected result:

- Stack starts in detached mode.
- Shop UI is available at <http://localhost:8080>.

If `make start-minimal` fails with cgroup/memory limit errors,
follow the cgroup workaround below and retry with the generated
`docker-compose.minimal.no-limits.yml`.

## Common run commands

- Full stack start: `make start`
- Minimal stack start: `make start-minimal`
- Stop all stack resources: `make stop`
- Restart one service: `make restart service=<name>`
- Rebuild + restart one service: `make redeploy service=<name>`
- Run integration tests: `make run-tests`

## Compose file selection

Use this decision order:

1. Default to `make start-minimal` for quick validation.
2. Use `make start` only when your task needs full stack services.
3. If cgroup v2 memory limit errors occur, use `*.no-limits.yml`
   files generated by the workaround script.

## Cgroup v2 workaround (cloud agent VMs)

Cloud VMs may require Docker to use `cgroupfs`:

```json
{
  "storage-driver": "fuse-overlayfs",
  "exec-opts": ["native.cgroupdriver=cgroupfs"]
}
```

Compose memory limits can also fail in this environment. Generate
compose files with memory limits removed:

```bash
python3 -c "
import yaml
for f in ['docker-compose.yml', 'docker-compose.minimal.yml']:
    with open(f) as fh:
        data = yaml.safe_load(fh)
    for svc in data.get('services', {}).values():
        limits = svc.get('deploy', {}).get('resources', {}).get('limits', {})
        limits.pop('memory', None)
    with open(f.replace('.yml', '.no-limits.yml'), 'w') as fh:
        yaml.dump(data, fh, default_flow_style=False)
"
```

Then start with the generated file, for example:

```bash
docker compose --env-file .env --env-file .env.override \
  -f docker-compose.minimal.no-limits.yml up \
  --force-recreate --remove-orphans --detach
```

## Troubleshooting decision table

| Symptom | Likely cause | Action |
| --- | --- | --- |
| Compose fails with cgroup or memory limit errors | cgroup v2 constraints in cloud VM | Generate `*.no-limits.yml` files and start with those files |
| Prometheus image cannot be pulled from `quay.io` | Registry egress block | Pull from Docker Hub and retag to expected image name |
| Grafana keeps restarting due to plugin install failures | `grafana.com` blocked | Treat as non-blocking unless your task specifically needs Grafana plugins |
| `frontend-proxy` fails with Envoy validation errors (for example empty addresses) | Image/source mismatch with prebuilt tags | Rebuild `frontend-proxy` from local source with the target compose file |

Prometheus and Grafana are optional for core shop behavior. UI and
core service workflows can still be validated without them.

## Image mismatch recovery

If prebuilt `ghcr.io/open-telemetry/demo:latest-*` images do not
match local source, rebuild the affected service:

```bash
docker compose --env-file .env --env-file .env.override \
  -f <compose-file> build frontend-proxy
```

Then redeploy:

```bash
make redeploy service=frontend-proxy
```

## Validation matrix (run the smallest useful checks)

| Change type | Minimum checks | Expanded checks (if needed) |
| --- | --- | --- |
| Markdown/docs only | `make misspell` and `make markdownlint` | `make check` |
| Build/compose/infrastructure | Start stack (`make start-minimal`) and smoke check UI | `make start` and targeted service restart/redeploy |
| Service behavior affecting user paths | Start stack and verify impacted flow in UI | `make run-tests` when integration confidence is required |
| License/header-sensitive file changes | `make checklicense` | `make check` |

Notes:

- `make check` runs misspell, markdownlint, checklicense, and link checks.
- `make install-tools` installs local tool dependencies used by checks.

## Fast smoke checks

After startup:

```bash
curl -fsS http://localhost:8080/ > /dev/null && echo "UI OK"
docker compose --env-file .env --env-file .env.override ps
```

If a specific service is under test:

```bash
make restart service=<name>
```

## Commit and safety hygiene for agents

- Keep edits scoped to the requested task.
- Do not commit sensitive files (for example `.env`, credentials, shell history).
- Prefer targeted checks over full-suite runs unless required.
- If observability optional services fail but core flows are healthy,
  continue task work and record the limitation in your summary.
